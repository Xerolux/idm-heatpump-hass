# Release Candidate Evidence: 0.22.0-b4

Status: `BLOCKED` for stable promotion; automated validation passed. Makes
GLT room-temperature and humidity forwarding restart-safe on top of
0.22.0-b3.

## Scope

- **Interval refresh for room temperature, storage temperature and humidity
  (fixed, found in the #493 investigation):** the periodic interval pass
  rewrites the GLT registers even when the source value has not moved. The
  tolerance guard previously suppressed every rewrite of an unchanged value,
  so a controller or Modbus-service restart — which wipes the volatile GLT
  RAM inputs — left the external room temperature at its -1 sentinel until
  the source drifted beyond tolerance. Observed live on a Navigator 10
  (`T_NAV10_20.24-1580-g02a20b66f`) with a read-only 1 Hz register probe:
  `hc_d_ext_room_temp` (1656) and `ext_humidity` (1692) sat at the sentinel
  for over fifteen minutes after a 23-second Modbus-service restart while
  all sources were steady; the external-power registers recovered within
  ~5 s via their cyclic refresh. Wipe recovery is now at most one
  configured interval (default 300 s). Event-driven writes keep the
  tolerance skip, so bursty sources neither spam writes nor trip the write
  cooldown. PR #520.

Motivation: live read-only register probing on the maintainer's reference
plant during the #493 investigation.
