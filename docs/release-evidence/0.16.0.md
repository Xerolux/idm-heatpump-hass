# Release Candidate Evidence: 0.16.0

Status: `BLOCKED`

`BLOCKED` is the accurate state of this record, and the stable tag was cut
anyway. That is a deliberate maintainer decision taken at release time, not an
oversight, and it is written down here rather than hidden behind a green
checkmark. Three gates from `docs/RELEASE_PROCESS.md` are open:

- **Gate 6 (soak).** `0.16.0-rc.6` was published on 2026-08-27T18:10:39Z and
  the stable tag follows on 2026-08-28, so the required seven consecutive
  24-hour periods on an unchanged candidate did not elapse. The RC6 record put
  the earliest eligible completion at 2026-09-03T18:10:39Z. Only the start
  observation exists; the midpoint and final observations do not.
- **Gate 3 (live hardware follow-up), KNX part.** No telegram from the KNX
  bridge has been decoded by a physical KNX device. Group-address
  interoperability on the wire and the bus load of a first full export are
  unverified, because no IDM group addresses were imported into ETS on the
  reference installation. This is why the bridge ships labelled *experimental*
  in the options flow, the documentation and the startup log.
- **Gate 3 (live hardware follow-up), model part.** Navigator 2.0 and
  Navigator Pro coverage remains community-reported. The maintainer reference
  system is a Navigator 10.

The automated preflight is complete and green. **No integration code changed
between `0.16.0-rc.6` and `0.16.0`**: the diff is the manifest version bump,
the changelog, this record and the documentation that states the current
version. The RC5 and RC6 live evidence therefore describes exactly the code
this tag ships, and the rows below that are inherited from those candidates are
marked as such.

   record datapoint encoding and first-export bus load once a real device has

2. Continue observing `0.16.0` on the maintainer Navigator 10 through
   2026-09-03, the date the soak would have ended, and record anything that
   would have blocked the tag.
3. Keep collecting Navigator 2.0 and Pro reports; the model gate stays open.
4. Publish a patch release rather than re-tagging if any of the above surfaces
   a regression.
