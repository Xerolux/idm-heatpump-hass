# Release evidence: 0.26.6

## Scope and release decision

The maintainer explicitly requested a new stable release in the 0.26 series
following the authorized field test and local patch installation. This record
separates observed results from hypotheses; it is not a claim of a seven-day
candidate soak, fleet-wide compatibility or a fresh hardware installation from
the published ZIP. That longer stable-candidate process was not completed for
this deliberate, default-off fast-follow patch. Prepared by Codex from the
maintainer-authorized session on 2026-11-07; no maintainer signature is fabricated.

- Candidate: `v0.26.6`; API requirement `idm-heatpump-api[web]==2.16.0`.
- Minimum Home Assistant: 2026.11.0. Runtime dependencies are unchanged.
- Hardware observation: Navigator 10, firmware `T_NAV10_20.24-1580-g02a20b66f`.
- Communication: HA shared Modbus transport with the local web supplement;
  controller messages were read through HA. No second direct device socket was opened.
- The permanent workaround is off by default and was explicitly enabled by
  the owner for the field installation through the standard options flow.

Debug logging was restored to its previous WARNING level. No PV-surplus
value, system mode or heating target was changed for the nonzero production
test. A manual zero restore attempt hit the existing cooldown after automatic
forwarding had already restored zero; the final observed production was zero.

## Interpretation and boundaries

The observations support a zero-production-dependent controller connection
assessment on this plant. They do not prove a universal firmware defect, a
specific RAM TTL/watchdog or that every message 20300 shares the same cause.
The separate #493 battery/display-retention report remains open evidence.
An HA number state can be optimistic; proxy/cache readbacks and successful
writes must be distinguished from the controller's continuously processed value.
The exact controller-internal algorithm was not captured by the web-capture
tool or a ModBridge packet trace in this session.

The fix substitutes 0.01 kW only for a valid, exactly zero PV-production source.
Positive readings use ordinary live forwarding and kW rounding. Invalid,
unavailable and unmapped sources remain skipped. Source sensors, surplus,
battery values and derived household balance retain measured values. Controller
PV-derived displays/statistics can nevertheless include artificial production.
