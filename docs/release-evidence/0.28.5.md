# Release evidence for 0.28.5

The maintainer requested a stable patch for the debug logging added after [issue #719](https://github.com/Xerolux/idm-heatpump-hass/issues/719). The runtime change adds messages to the existing DHW boost restoration path. The release retains the 0.28.4 write interval, retry logic and API 2.17.0 pin.

## Cancellation scenario

A simulated Navigator 10 starts with a 52 °C setpoint. The test starts a 60 °C boost, cancels it once and simulates EEPROM refusals with 42.2 and 10.4 seconds remaining. The next eligible coordinator update writes 52 °C. The captured debug log contains one wait message and one successful setpoint write. The simulated controller receives a single successful write during recovery.

The field report and its log established the cause of the early refusals. The new messages document integration-side writes. Confirmation of the restored setpoint on the reporting controller remains open. This same-day diagnostics release used automated tests without a physical boost or an extended hardware soak.

## Local verification

Both coverage runs passed 3,738 tests and skipped two. Integration coverage reached 98.35% and config flow coverage reached 100%. All 15 lifecycle tests passed on Home Assistant 2026.11.0. Strict mypy checked 91 source files. Ruff lint and formatting checks passed, and the dependency check confirmed the 2.17.0 API pin.
