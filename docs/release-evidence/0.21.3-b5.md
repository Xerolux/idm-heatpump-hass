# Release Candidate Evidence: 0.21.3-b5

Status: `BLOCKED` for stable promotion; automated validation passed. Carries
the first fix for the open battery-display report #493.

## Scope

- The periodic external-power pass refreshes GLT RAM inputs at a fixed
  firmware-safe cadence of 5 s instead of sleeping `max(30, interval)`. The
  reporter's b4 debug log established the mechanism: `battery_soc = 90.0`
  written every 60 s with quiet sources, visible in the Navigator UI for
  ~10 s, then cleared to the unavailable sentinel — some Navigator firmwares
  (observed on NAV10_20.23-903) drop GLT RAM inputs roughly ten seconds after
  the last write. A 5 s refresh stays inside that hold window; the per-register
  write cooldown still throttles actual writes; sensor-driven forwarding is
  unchanged. The wiki setup advice (EN/DE) was corrected accordingly.
- The energy-manager and comfort-schedule loops are spawned as Home Assistant
  background tasks; the reporter's log shows the bootstrap timeout their
  never-finishing foreground tasks caused.

No cooldown policy, register encoding, setpoint or fallback-value changes
beyond the periodic cadence. Issue #493 stays open until the reporter
confirms on this beta.
