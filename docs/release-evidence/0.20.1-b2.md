# Release evidence: 0.20.1-b2

Date: 2026-10-01. Scope: automatic detection of differential-temperature
controlled heating circuits through the local web interface ([issue #429](
https://github.com/Xerolux/idm-heatpump-hass/issues/429)), Home-Assistant-owned
transport requirements, and the device-logic pin move to the API release that
carries the new frame.

## Implemented behavior

- Every Navigator 10 web poll evaluates the complete-plant `system/overview`
  frame; heating circuits whose regulation type marks them differential are
  detected with zero configuration wherever a web PIN is set up. The manual
  selection from 0.20.1-b1 remains the authoritative override and covers
  installations without the web supplement.
- The diagnostics export gains `heating_circuit_types` (circuit letters with
  the controller's raw type numbers, nothing personal), so the detection
  mapping can be confirmed from a diagnostics download.
- The transport packages (`modbus-connection`, `tmodbus`) are stated as
  minimum requirements — Home Assistant's own modbus integration adopted them,
  and hassfest rejects exact pins of packages Home Assistant owns. The floor
  is the validated pair; the daily freshness pipeline keeps raising it after
  validating runs and never crosses a major.
- Device logic moves to `idm-heatpump-api[web]==2.14.0` for the new read-only
  `read_system_overview()`; strictly read-only, no level logins, no writes.

## Live verification (read-only, maintainer's plant, 2026-10-01)

- The `system/overview` frame answers on a plain PIN session at userlevel 0
  and lists both configured circuits with `type: 2` (normally regulated,
  matching *Geregelt*). The level-2 Heizsystem setting page that exposes the
  labelled dropdown is gated per settingId (setting page 4747 answered while
  the controller was display-unlocked at Fachmann Ebene 2 and stopped
  answering after it relocked) — the detection therefore uses the ungated
  frame.
- Web login levels were probed directly: only level 0 (PIN) and level 4
  (technician, N2_EASYCONFIG QR) are supported; level 2 is rejected
  (`"specified userlevel [2] is not supported!"`). The integration performs
  no level logins — elevation stays the user's own manual action.
- The regulation-type numbering follows the Heizsystem choicelist order with
  `2` live-confirmed; the differential value `4` rests on that order. The
  issue tracker asks the #429 reporter for confirmation via the new
  diagnostics field; the manual selection is unaffected either way.
