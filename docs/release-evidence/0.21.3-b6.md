# Release Candidate Evidence: 0.21.3-b6

Status: `BLOCKED` for stable promotion; automated validation passed. Carries
the advisor room-temperature plausibility fix (#504).

## Scope

- AdvisorEngine routes every room-temperature read through `_room_temp()`,
  applying the advisor's plausibility range (0-50 C) on top of the finite
  check: `_primary_room_temp`, the room-deviation metric loop and the
  flow-pair gate treat out-of-range values as missing, and the heat-demand
  plan falls back to its indoor default. Uninitialized-memory readings
  (observed as -327.33 on a Navigator 2.0 without a wired room sensor) no
  longer feed the heat-loss regression or any metric.
- The curve producer skips room-deviation baselines whose median exceeds the
  plausible room/setpoint span, so analytics storage polluted before the fix
  cannot produce heating-curve recommendations while the rolling window
  clears.
- `capabilities.room_temperature` is reported only for range-valid readings.

No polling, transport, write-path or register changes. The issue was closed
by the deterministic fix; the reporter's follow-up is welcome but not
required for correctness.
