# Release Candidate Evidence: 0.22.0-b2

Status: `BLOCKED` for stable promotion; automated validation passed. Quiet
connection-outage handling on top of 0.22.0-b1.

## Scope

- **Quiet outage window (fixed):** connection-class poll failures
  (`cannot_connect`, `modbus_connection_refused`, `modbus_timeout`,
  `host_not_found`) pass quietly for five minutes before the coordinator
  escalates. Inside the window a failed poll returns the last snapshot
  merged with live web metadata — no `UpdateFailed`, no repair issue, no
  error line — with one gray info line on loss and one on recovery.
  Connection-class write failures join the same window (debug log, no
  `write_rejected` repair); a delivered write closes the outage early.
  Failures the controller itself answers with (wrong slave ID, firmware,
  no data) escalate immediately; an outage that outlasts the window
  escalates to the previous visible behavior, including the calm
  `modbus_degraded_web_active` notice and the once-per-outage error line.
- **Forwarder log level (fixed):** the room-temperature, humidity and
  external-power forwarders log their once-per-outage line at info instead
  of warning; the coordinator owns the visible outage announcement.
- **Repository hygiene:** 17 coverage data files accidentally committed by
  the coverage push (PR #503) were removed, and `.gitignore` now covers
  the suffixed `.coverage*` variants (PR #513). Not part of the release
  artifact.

Motivation (maintainer log, 2026-10-13 morning): a flapping proxy host
produced 69 write-delivery warnings and 8 coordinator/core error pairs
across sub-minute outages; users reading the log history afterwards filed
reports for outages that had long self-healed.

No polling, transport, dependency or write-path policy changes beyond the
above. The #493 GLT RAM refresh fix from 0.21.3-b5 remains pending the
reporter's confirmation.
