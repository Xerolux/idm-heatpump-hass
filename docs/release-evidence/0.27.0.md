# Release evidence: 0.27.0

Scope: stable cut of the 0.27 *measurability* line (request-level transport
metrics, fixable scan-interval repair, localized advisor titles,
firmware-orientation restart persistence, PV zero-power heartbeat rebuild,
register-84 battery documentation). Prepared from the maintainer-authorized
session on 2026-11-16 that produced the release; the full local gate set was
executed in that session. No submission to IDM Tools, no firmware observation
query and no fresh hardware installation from the ZIP was performed.

## Scope and release decision

- Candidate: `v0.27.0` cut from `d130561`; API requirement stays
  `idm-heatpump-api[web]==2.16.2` as pinned by 0.26.12; minimum Home Assistant
  2026.11.0.
- The stable ships the 0.27.0-b4 line unchanged: after the b4 tag
  (2026-11-10) only wiki documentation landed (PR #706, hot water station flow
  finding). The changelog folds b1–b4 into the stable section without dropping
  a change; the wiki changelog pages keep the beta milestones and add the
  stable summary.
- No new plant write path ships enabled: the request metrics are passive (no
  additional request), the scan-interval repair changes nothing unconfirmed,
  and the PV zero-power workaround stays off unless explicitly enabled.

## Change under test

| Area | Result | Limit |
|---|---|---|
| Request-level timing (#694) | Every transport request — FC03/FC04/FC16, FC01/FC05 coils, bisect re-reads — timed passively in a bounded 100-request window; opt-in sensor and diagnostics snapshot | Measures the transport boundary, not end-to-end coordinator latency |
| Scan-interval repair (#695) | Suggested interval from bounded poll-duration history (p95 ÷ warning ratio, 5 s steps, 5–300 s); *Fix it* pre-fills, validates, reloads once | Suggestion only; nothing changes unconfirmed |
| Localized advisor titles (#696) | Stable title keys with pre-formatted values rendered DE/EN incl. Assist; `title_localized` added additively | English `title` stays the documented data field for events/storage/diagnostics |
| Firmware restart persistence | Last validated catalog answer stored in the config entry and restored at startup; persistent notice linked to the entry; first check within 15 min | Covered synthetically; no live plant re-check for this cut |
| PV zero-power heartbeat | 10/20 W alternation every minute; production below the 5 W register resolution substituted | Mechanism validated by a Navigator 10 live series (message 20300 latches on an unchanged register); opt-in, off by default |
| Register-84 battery documentation (#493) | Setup/options/reconfigure help names the requirement; register reference and Findings carry the evidence with its scope | Documentation only; IDM confirmed only register 84, not a whole-cycle write duty |

## Interpretation and boundaries

- Rollback to 0.26.13 restores the previous firmware-notice behavior (sensor
  blanks until the next check; a dismissed — not acknowledged — notice can
  surface one last time); the request-metrics sensor disappears with its
  option, and the PV workaround returns to the constant substitute.
- The frozen-register mechanism behind message 20300 is established on a
  Navigator 10 live series; other controller families inherit the heartbeat
  only through the same opt-in option and were not separately re-validated.
- The hot water station flow finding (PR #706) is wiki documentation of an
  inferred physical line; it ships no code.
