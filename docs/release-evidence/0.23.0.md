# Release evidence: 0.23.0

Date: 2026-10-21. Scope: the stable cut of the 0.23 line — the fourteen
prereleases b1–b14 (2026-10-17 through 2026-10-20) folded into the single
stable changelog section; manifest and documentation versions moved to
`0.23.0`. No code changed against 0.23.0-b14; the delta is changelog,
manifest version and version-bearing documentation only.

## Release line summary

- b1: per-register "not present" sentinels and the web `---` placeholder
  handling from #532's evidence (device logic `idm-heatpump-api`
  2.14.3).
- b2: thermal power fallback to `current_power` (1790) when 4126 reads
  0.0 kW — COP, energy totals and advisor models work on plants without
  a Vortex sensor; entity cleanup on the normal setup path; energyflow
  availability.
- b3: operation-reason fix — idle web demand labels never mask active
  operation; `Defrosting` takes precedence over the flow-temperature
  loop.
- b4: field-feedback batch #537/#538/#539 — no more coordinator-wide
  unavailability windows after GLT forwarding passes (write-confirmation
  scheduling), English-only operation-reason labels, no-TWT fake flow
  gated out of advisor quality.
- b5: recommendation topic superseding; web values fill registers whose
  Modbus reading is the not-present pattern (discussion #516).
- b6: hardening pass — flow plausibility 0–250 L/min, advisor polling
  companions, per-task write-confirmation tracking, forwarding dedup,
  background task registration, unload cancels the forecast task.
- b7: building model learns only from space heating (#546); grid-meter
  household derivation pauses on an invalid battery source (#519).
- b8: register 1072 is a word-swapped FLOAT32 (discussion #516, device
  logic `idm-heatpump-api` 2.14.4).
- b9: energy-manager option translations in both UIs; translation-parity
  and German-register-reference guards; single-Modbus-client rule
  documented.
- b10: advisor review pass — DHW windows in local time, quarter-hour
  feed folding, price dedup, naive-timestamp rejection, `refreshed_at`
  TTL anchor, store-write throttling, per-mode COP statistics
  (`energy_cop_heating_*` / `energy_cop_dhw_*`).
- b11: efficiency-score sensor publishes its score (int hotfix, found
  live).
- b12/b13: PV forecast from the core Forecast.Solar integration and the
  registry-platform fix that made it match on real installations.
- b14: heat-pump-level flow deviation sensor, published in pure heating
  mode only (24 h read-only probe on the reference plant).

## Field soak

The line ran live on the maintainer's Navigator 10 plant (HA entry
through the Modbus proxy, web supplement active, Forecast.Solar, Ostrom
price and CO₂ configured) from 2026-10-17, beta by beta: b2's thermal
fallback filled COP and energy totals, b4's scheduling fix ended the
12-second unavailability windows, b6/b7 hardened the advisor, b8 turned
the flow entity from fake values into real L/min, and the b10–b13
advisor work was verified hour by hour — ending in the observed
in-window DHW charge on 2026-10-20 (three charges 12:08–13:59 local, the
13:25–13:59 segment inside the recommended 13:00–16:00 PV window;
observed 7-day COPs 3.65 heating / 3.04 hot water). External reporters
validated the register-typing fix live on two plants (discussion #516,
aivatco "looks good") and drove #532, #537–#539 and #546 to closed with
their evidence. The unchanged b14 candidate soaked for about one day
before this cut — short of the seven-day gate, and the line's code
changed almost daily. The maintainer decided to cut anyway: the only
write-path changes in the line confine themselves to write-confirmation
scheduling (#537 and its per-task follow-up, running live on the
reference plant since 2026-10-17/18), the register-map change is a
read-typing correction, the advisor and storage changes are local
(additive storage fields, one-time building-model relearn, per-mode
counters starting at zero), and no EEPROM-sensitive register is touched
by any new path (see the 0.23.0 release decision on the stability page).
