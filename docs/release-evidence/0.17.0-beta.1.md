## Candidate-Specific Risk

The audit touched code paths that a unit test can only partly speak for. Give
these priority during the live smoke test:

- **Model detection.** Reconciliation of the Modbus probe, stored entry data,
  the web supplement and a manual override moved into `model_resolution.py`.
  Behaviour is meant to be identical; SMOKE-03 and SMOKE-09 are what proves it
  on hardware, in particular for a Navigator 10 whose firmware refuses register
  4108.
- **Setup and teardown.** A failed setup now tears down what it already built,
  background tasks are tied to the config entry, and a poll can no longer
  outlive it. SMOKE-08 covers reload, unload and re-enable.
- **Writes.** The translated-write path is shared by all five writable
  platforms and the domestic hot water boost no longer fights the write pacing.
  SMOKE-06 and SMOKE-07 stay strictly on documented safe registers.
- **Forwarding.** Forwarded room temperatures are now converted to degrees
  Celsius. An installation that forwards a Fahrenheit or Kelvin source is the
  case to watch in SMOKE-11.
- **Runtime pins.** Both moved in this candidate, which is why the soak clock
  starts here and not at `0.16.2`.
