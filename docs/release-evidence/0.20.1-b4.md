# Release evidence: 0.20.1-b4

Date: 2026-10-01. Scope: self-healing Modbus outages without alarming
users — the calm degradation notice while web data flows, log quieting, and
the recovery watchdog that reloads entries stuck in Home Assistant's
setup-retry backoff.

## Implemented behavior

- A failed Modbus poll with the web supplement delivering raises the calm
  notice `modbus_degraded_web_active` (data continues via the local web
  interface, auto-clears on the first successful poll) instead of the
  classified connection error; without web, the previous issue stands.
- The failure log is one ERROR per outage, DEBUG afterwards (previously one
  ERROR per scan interval).
- When `async_setup_entry` raises `ConfigEntryNotReady`, a recovery watchdog
  TCP-probes the configured Modbus endpoint once a minute (connect + close,
  nothing sent) and reloads the entry automatically after consecutive
  successes, with a ten-minute per-entry cooldown. The watchdog only runs
  while an entry is in setup retry and owns no task on a healthy
  installation — the real-HA lifecycle no-leaked-tasks assertion stays
  meaningful and green.
- No user-visible entity changes; no configuration migration.
