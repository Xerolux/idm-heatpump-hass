# Release Candidate Evidence: 0.16.0-rc.2

Status: `BLOCKED`

`BLOCKED` is the expected state for this prerelease evidence record. It carries
forward every open item from
[`0.16.0-rc.1.md`](0.16.0-rc.1.md): a clean Home Assistant artifact smoke test,
Navigator 2.0/Pro coverage, the seven-day soak and the final maintainer
sign-off all remain open before a stable `0.16.0` cut.

This candidate changes one integration code path over `0.16.0-rc.1`: the device
hierarchy registers its heating circuits, optional modules and rooms as child
devices on Home Assistant `2026.9` and newer, falling back to the previous
`via_device_id` links on `2026.8`. It also adds forward-compatibility evidence
for `2026.9`, a continuous integration fix, and documentation corrections.
Entity IDs, unique IDs, register addresses, write paths and the dependency pins
are unchanged.

## Child-Device Hierarchy Evidence

Adopted in this candidate. Verified by driving the integration's own
`precreate_main_device`, `build_subdevice_info` and
`cleanup_stale_hierarchy_devices` against a real `2026.9.0b0` `DeviceRegistry`,
not against the unit-test doubles.

| Check | Result | Evidence |
|---|---|---|
| Upgrade from a `0.16.0-rc.1` `via_device_id` hierarchy | `PASS` | every device ID preserved across the conversion, so entities, areas and automations keep pointing at the same devices |
| Heating circuits and optional modules become children of the controller | `PASS` | `parent_device_id` resolves to the main device |
| Rooms become children of their zone module | `PASS` | `parent_device_id` resolves to the zone module |
| Zone modules stay ordinary `via_device_id` devices | `PASS` | required: a child device can't be the parent of another child device, and the rooms need a real parent |
| Nesting a child below a child is refused | `PASS` | `DeviceInfoError` from the real registry, which is why the zone module is not converted |
| The generated `device_info` is accepted by the registry | `PASS` | `async_get_or_create_child` accepted it unchanged and the device ID stayed stable |
| Deleting a zone module cascades to its rooms | `PASS` | confirmed against the real registry; the cleanup therefore keeps a module while a room below it survives |
| Stale child devices are removed, live ones kept | `PASS` | a de-configured module was removed while the circuit and room survived |
| Home Assistant `2026.8` fallback | `PASS` | `child_devices_supported()` returns `False` and the hierarchy uses `via_device_id`, covered by unit tests for both paths |

One constraint worth recording for future work: Home Assistant refuses to
convert a device into a child device while the config entry that registered it
is still loaded. A real upgrade is unaffected, because the devices come from the
previous session, but an integration must never register the same identifiers
first as a main device and then as a child within one run.
