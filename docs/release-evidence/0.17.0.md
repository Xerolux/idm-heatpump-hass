# Release Evidence: 0.17.0

Status: `BLOCKED`

`BLOCKED` is the accurate state of this record, and the stable tag was cut
anyway — the same deliberate maintainer decision pattern as `0.16.0` and
`0.15.0`, taken at release time and written down rather than hidden behind a
green checkmark. The open gates:

- **Gate 6 (soak).** `0.17.0-beta.4` was published on 2026-09-13 and the
  stable tag follows the same day, so the required seven consecutive 24-hour
  periods on an unchanged candidate did not elapse for `beta.4`. Mitigating:
  `beta.1` (2026-09-09), `beta.2` (2026-09-09) and `beta.3` (2026-09-11) were
  in the field for four days with no user-reported regression, and the only
  code delta from `beta.3` to `beta.4` is the Navigator 1.7 feature set,
  which cannot activate on a shared-family controller.
- **Gate 3 (live hardware follow-up), Navigator 1.7 part.** No 1.x controller
  is maintainer-owned. The 1.7 register map is built from the official iDM
  1.x table and covered by the API's test suite, but no physical device has
  confirmed detection, sensor values or PV writes. The call for testers is
  [#319](https://github.com/Xerolux/idm-heatpump-hass/issues/319); the wiki
  compatibility matrix lists the family as `expected`.
- **Gate 3 (live hardware follow-up), KNX part.** Unchanged from `0.16.0`:
  no telegram from the KNX bridge has been decoded by a physical KNX device.
  The bridge remains labelled *experimental*.
