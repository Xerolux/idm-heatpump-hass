# Release Candidate Evidence: 0.16.0-rc.4

Status: `BLOCKED`

`BLOCKED` is the expected state for this prerelease evidence record. It carries
forward every open item from [`0.16.0-rc.3.md`](0.16.0-rc.3.md) — a clean Home
Assistant artifact smoke test, Navigator 2.0/Pro coverage, live KNX bus
evidence, the seven-day soak and the final maintainer sign-off — and adds one of
its own: **no installation has yet been upgraded to this candidate to confirm
that the translated entity names arrive without entity-ID churn.**

This candidate changes how every entity is *named*. Entity IDs, unique IDs,
register addresses, write paths, the device hierarchy, the polling behaviour and
the dependency pins are unchanged from `0.16.0-rc.3`, but the visible name of
every entity now comes from the translation files instead of a hardcoded German
string, so an English Home Assistant shows different (English) names after the
upgrade.

It also carries two changes to the experimental KNX bridge, merged after the
quality-scale work:

- **The bridge answers read requests.** `0.16.0-rc.3` ignored `GroupValueRead`,
  so a push-button asking for a value after a restart stayed blank until the
  next change happened to be sent. The bridge now replies with the value the
  heat pump currently reads, as a `GroupValueResponse` — what the BAOS gateway
  it replaces does. New option *Answer read requests*, on by default.
- **ETS group address files.** `scripts/generate_knx_group_addresses.py` writes
  the bridge's addresses as an ETS 6 group address import plus a CSV reference,
  with two generated examples in `docs/examples/knx/`. Nothing about this runs
  at integration runtime; it is a developer script and two data files.

The bridge remains **experimental** and off by default, and is still labelled
as such in the options flow, the documentation and the startup log.

Because this candidate changes integration code, the seven-day soak clock
restarts here; it does not inherit `0.16.0-rc.3`'s elapsed time.
