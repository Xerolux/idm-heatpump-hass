# Release evidence for 0.28.8

[Issue #750](https://github.com/Xerolux/idm-heatpump-hass/issues/750) asked for read-only Navigator 10 entities for a hydraulic visualization. The reporter's sanitized IDM Web Capture of an SLM 6-17 on `NAV10_20.24-1124-g509fead95` verified the sources: the structured `system.diffTempControl` block (`temperatures.buffer` 20.1 °C equals the B84 setting row, `reference` 40.3 °C, `pumpActive` false) and the until-then unmapped M71/M88/M61 rows of settings 4782/4789, which `read_data()` already fetched. API 2.18.0 maps them; this release publishes six read-only web entities — `web_diff_temp_buffer_temp`, `web_diff_temp_reference_temp`, `web_diff_temp_pump_active`, `web_diff_temp_pump_signal` (−1 % off marker dropped), `web_hgl_mixer_signal` and `web_valve_heating_cooling` (M61 wording passthrough) — without any new controller request. The M61 value cell was redacted by the capture sanitizer; the entity therefore claims no value domain beyond the controller's own wording.

Verified locally against the built 2.18.0 wheel in the real-runtime venv (Home Assistant 2026.11.0): full suite 3765 passed with 98.36 % coverage, `config_flow` at 100 %, strict mypy clean, ruff check/format clean (0.17.6), and the real-Home-Assistant smoke leg (16 tests) green. API 2.18.0 shipped its own gates first: 766 tests at 90 % coverage, strict mypy, ruff, wheel build, twine check and a clean-venv import; the compatibility matrix records the pair.

This is a same-day additive patch: every new entity is read-only and appears only where the controller delivers the row. Field confirmation on the reporter's plant and the seven-day soak remain open; the next runtime-dependency change restarts the soak clock per the release process.
