# Release evidence: 0.20.1-b5

Date: 2026-10-02. Scope: the cosmetic entity-ID shortening for
differential-temperature circuits from #429 — the plain device name, the
one-time registry migration for IDs registered under the suffixed name, and
the wiki cleanup around differential-circuit detection — plus the
documentation follow-up for the non-terminating Navigator 1.x priority
charge reported in #319.

## Implemented behavior

- The sub-device of a differential circuit is named `Heizkreis D` and carries
  the circuit type on its model (`Differential temperature control`), like
  every other sub-device scope (plain name, type on the model). The former
  `(Differenztemperaturgeregelt)` name suffix was the reason Home Assistant
  doubled the length of every new circuit entity ID: the registry prefixes
  each new entity ID with the slug of the device name.
- New entities of a differential circuit therefore register as
  `heizkreis_d_…`, matching every other circuit (`has_entity_name` object-ID
  derivation; verified against the Home Assistant 2026.8.1 entity registry
  source — `object_id_base` is prefixed with the device name,
  `suggested_object_id` is not, and no per-entity override is needed).
- A one-time migration `shorten_legacy_differential_entity_ids` runs on
  setup after `cleanup_deconfigured_heating_circuit_entities` (both the
  Modbus and the web-only path). For entities of the entry whose entity ID
  still contains the `heizkreis_{circuit}_differenztemperaturgeregelt_` slug
  segment of a circuit that is differential now, the segment is rewritten to
  `heizkreis_{circuit}_` — language-agnostic, because it matches the
  device-name slug, not the translated entity name
  (`…_temperaturdifferenz_hk_d` and `…_temperature_difference_hc_d` alike).
  A `ValueError` from the registry (short ID already owned by another
  entity) leaves the long ID working; entity IDs without the segment,
  renamed by the user or belonging to other circuits, are untouched.
- Wiki: the English and German configuration and entity pages described the
  differential-circuit selection as manual without automatic detection,
  contradicting the automatic web detection introduced in 0.20.1-b2 (whose
  paragraph had also been appended next to room names). Both pages now
  describe the detection with the option, and the entity pages document the
  ID shortening and its migration note.
- Issue #319 field report: on the reporter's 1.x firmware the c3003
  priority charge keeps the controller in DHW mode until error 020 (HP flow
  maximum temperature), while the `system_mode` *Warmwasser einmalig* path
  terminates normally. The button is unchanged (single FC05 write of ON; the
  coil falls back to 0 on verified firmware, so nothing writes OFF); the
  entity documentation in both languages now describes the firmware
  behavior, names the working alternative, and asks for reports.
