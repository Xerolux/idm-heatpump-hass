# Release evidence: 0.28.1

## Scope

This maintenance candidate preserves the operation-analysis storage schema.
It bounds checkpoint delays under continuous polling, ignores the outcome
of a hot-water charge interrupted by a long poll gap, and splits observed
hot-water runtime at local midnight. Capture failure tests use simulated
connection refusals. The Modbus polling plan and controller write paths
are unchanged.

## Stable release decision

The maintainer authorized a same-day stable patch on 2026-11-18 with an
explicit exception to the seven-day candidate soak. Publication depends on
green CI and real Home Assistant smoke tests. This is a read-only accounting
patch with no dependency, register map, or controller write changes.
A normal field charge and a live polling interruption were not replayed.

## Validation

- Regression tests cover repeated fast polls, resumed persistence, a demand
  falling edge after a gap, an active charge after a gap, and local midnight.
- The real Home Assistant 2026.11.0 store was exercised with a scaled
  checkpoint interval and wrote observed history while polling continued.
- The dependency pin remains `idm-heatpump-api[web]==2.16.2`. The minimum
  Home Assistant version remains 2026.11.0.
- Published ZIP and SHA-256 verification are performed after the stable tag.
- No controller writes or intentional live communication interruptions
  were used for these checks.
