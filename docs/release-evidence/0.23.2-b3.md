# 0.23.2-b3 validation evidence

Date: 2026-10-25. This beta pins the API maintenance prerelease
`idm-heatpump-api[web]==2.14.5b2` (API PR #145, published on PyPI after API
release `v2.14.5b2`). The API change is library-side hardening only: model
detection batches its heating-circuit probes behind individual gate probes
with a per-slot fallback (identical results on every test fixture), honest
`dry_run` labeling of write plans, shared timeout/error-mapping helpers, a
latent `exclude_from_write` float-comparison fix, and expanded coverage for
the key-based write API and the Pymodbus coil extension. No register-map
changes. This beta does not claim to fix the remaining Navigator 1.7
web/status issues (#577) or the recurring battery-display issue (#493).

## Reproducible dependency pair

- Integration: `0.23.2-b3`.
- API: `idm-heatpump-api[web]==2.14.5b2`, published on PyPI after API PR #145.
- Transport floors: `modbus-connection>=4.12.4`, `tmodbus[async-serial]>=0.6.2`.

## Local validation

- API: 637 tests passed in the release tree; 89.10% coverage against a 75%
  gate. Ruff lint/format, strict mypy, `python -m build`, `twine check` and a
  clean-venv wheel import passed. The GitHub release is marked as a
  prerelease and the PyPI JSON API served `2.14.5b2` before this pin.
- Integration: 3,149 tests passed against the published `2.14.5b2` artifact;
  99.82% coverage against a 95% gate. A separate complete run passed with
  100% config-flow coverage.
- Ruff lint/format and strict mypy passed on the integration tree.
- `scripts/check_dependency_pins.py`: every exactly pinned runtime dependency
  is the newest release on PyPI (`2.14.5b2` is current).
- `scripts/check_documentation_versions.py`: current integration and runtime
  versions in registered documentation match the manifest (after `--update`).
- Real-Home-Assistant lifecycle smoke tests and HACS/hassfest validation run
  in CI on this pull request.

## Evidence boundaries

Detection-request batching is covered by fake-transport unit tests in the API
repository (fast path, short-batch fallback, failed-batch fallback) and by the
full integration suite here; no physical controller was contacted for this
release. Detected models, heating circuits and entities are unchanged by
construction, but field confirmation of the reduced setup request count on a
live Navigator remains open, as do #577, #493 and the diagnostic-data
collection issue #594.
