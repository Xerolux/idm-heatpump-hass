# Release evidence: 0.26.11

Scope: self-explanatory firmware repairs notice (presentation only) and the
tested `idm-heatpump-api` 2.16.2 pin. Prepared from the maintainer-authorized
session on 2026-11-09 that produced the release; the full local gate set was
executed in that session. No submission to IDM Tools, no firmware observation
query and no fresh hardware installation from the ZIP was performed.

## Scope and release decision

- Candidate: `v0.26.11`; API requirement `idm-heatpump-api[web]==2.16.2`;
  minimum Home Assistant 2026.11.0.
- The repairs notice gains a card-level `description` naming the installed and
  the community-observed version; title, fix flow and acknowledgement behavior
  are unchanged.
- The API pin follows 2.16.2 (PyPI, 2026-11-09). The patch teaches the API's
  Navigator 10 web reader to distinguish capture-confirmed
  unavailable-circuit notes from malformed responses; no register map or write
  behavior change. The generated register reference (687 logical definitions,
  154 for Navigator 1.7), the entity metadata catalog and the entity
  translations regenerate byte-identical apart from the version stamp.
- Session hardening shipped with this release: the pin updater now covers the
  parity-test rejection fixture, and the dated pin statements in the Stability
  page (unchanged-from 0.26.1 / 0.26.0 / 0.25.0 comparisons) are restored to
  their published versions and registered as history statements, so future pin
  bumps cannot rewrite them again.

## Change under test

| Area | Result | Limit |
|---|---|---|
| Repairs card description | Names `{installed}` and `{observed}` directly on the card, points to *Latest reported firmware* on the Telemetry device | Presentation only; the fix flow, acknowledgement fingerprint and notice lifecycle are untouched |
| Placeholder contract | New contract test verifies both locales use only supplied placeholders and keep title/description parity | Tests translation strings, not frontend rendering |
| API 2.16.2 unavailable-circuit split | API-side refinement behind the existing response-error contract; integration suite and real-HA smoke pass against it | No field capture replayed locally; classification is API-contract-tested, not field-proven |
| Pin updater history guard | Dated Stability-page statements restored and protected; parity-test fixture now covered by the updater | Guard patterns are anchored to those sentences; new dated prose must be registered explicitly |

## Interpretation and boundaries

- The richer repairs card is a translation-string change; existing
  acknowledgements, entity IDs, consent state and the notice lifecycle are
  unchanged, and rollback is safe.
- The API 2.16.2 refinement was exercised through the unit suite and the
  real-HA smoke leg, not against a live Navigator 10 web interface.
- No live plant, no fresh ZIP installation and no IDM Tools traffic were
  involved in preparing this release.
