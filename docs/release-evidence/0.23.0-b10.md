## Live upgrade and observation

Completed 2026-10-19. The reference plant (AERO ALM 6-15, Navigator 10,
firmware `T_NAV10_20.24-1580-g02a20b66f`, entry via the local proxy) was
HACS-updated to b10 at 07:03 UTC (`update.install` with the explicit
version; the HACS cache had not yet listed b10 and the explicit install
refreshed it) and fully restarted at 07:05 UTC — a config-entry reload
would not have re-imported the new modules (see the b8 record). Updated
again to b11 and restarted at ~07:52 UTC.

Findings, mapped to the verification plan:

1. **Per-mode COP sensors (PASS, heating half live)** — all six entities
   registered (`…_cop_der_warmepumpe_heizen/warmwasser_gesamt/heute/…`).
   After the first pure heating cycles the heating sensors publish:
   `heizen gesamt` 3.52 → 3.53 with attributes `electrical_kwh: 0.25`,
   `thermal_kwh: 0.89` (0.89/0.25 = 3.56; the sensor COP is the
   energy-weighted ratio — consistent). The plant heated continuously
   during the observation window, so no pure DHW charge occurred yet; the
   DHW sensor stays `unavailable` until the next hot-water charge. The
   DHW attribution is the same code path with focused tests
   (`test_per_mode_cop_attribution_follows_the_operating_mode`); its live
   appearance is expected with the next charge and is tracked below.
2. **DHW window times in the local zone (N/A live / covered by tests)** —
   the reference plant has no dynamic price source configured
   (`dynamic_price_source: false` in the advisor capabilities) and no PV
   forecast entity, so no DHW window recommendation exists on this plant.
   The rendering path is covered by the unit suite with a pinned
   Europe/Berlin zone.
3. **One-time building-model relearn (PASS)** — after the update the
   heat-loss (`gebaudewarmeverlust`) and thermal-inertia entities are
   `unavailable` with the storage version bump (2 → 3); no errors in the
   log; the daily-baseline anomaly producers kept working.
4. **Advisor state survived the upgrade (PASS)** — the active
   recommendations (heating-curve HC A and HC D) and the observation clock
   (11.9 days, stage `recommending`, confidence level `very_high`)
   carried across both restarts; the b9-era store parsed with the
   additive `refreshed_at` field.
5. **Logs (PASS)** — the system log holds no idm-heatpump entries
   (no ERROR/WARNING) after both restarts and the observed heating
   cycles; Modbus polling via the proxy stayed clean.

**Live-found bug (fixed in b11, PR #561):** the health components
published the efficiency value (84) while `advisor_efficiency_score`
itself stayed `unavailable` — the engine rounded the score to a float and
the int-typed sensor rejected it. Earlier field passes had read the
missing sensor as expected lifecycle gating. On b11 the sensor publishes
(86 at the time of verification) with plausible attributes
(expected 3.83, deviation −6.8 %).
