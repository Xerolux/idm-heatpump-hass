# Release Candidate Evidence: 0.16.0-rc.6

Status: `BLOCKED`

This candidate supersedes RC5 after its live smoke test exposed a Home
Assistant startup-order race. If the IDM entry starts after KNX services are
registered but before the KNX runtime is ready, group-address event
registration now retries until it succeeds. RC5's latest-value command queue,
write guards and conservative 60-second EEPROM default are unchanged.

`BLOCKED` remains the correct stable-release verdict. Physical KNX
group-address telegram interoperability, first-export bus load, Navigator 2.0
and Pro coverage, the seven-day soak and final maintainer sign-off remain open.

## KNX and Hardware Scope

The reference installation runs Home Assistant `2026.9.0b0`, an active KNX
tunnelling interface and an IDM Navigator 10 heat pump. Private addresses,
tokens, serial numbers and customer data are intentionally omitted.

The RC5 live smoke established the exact regression and a safe boundary for
the RC6 retest:

- HACS installed RC5 and a full Home Assistant restart loaded 8 IDM devices
  and 218 entities;
- KNX receive mode stayed enabled while outgoing values, read responses and
  periodic resend remained disabled, so no bridge telegram could reach the
  physical KNX bus;
- the heating-circuit object group was temporarily selected for the narrow
  test, while no IDM group addresses existed in ETS;
- the log captured `knx.event_register` failing with
  `integration_not_loaded` because the KNX runtime finished after IDM;
- internal smoke events did not write the controller, and heating-circuit D's
  normal room setpoint remained exactly `22.0`.

RC6 must recover the event registration without a manual IDM reload. The only
authorized controller write remains the reversible D setpoint `22.0 -> 23.0 ->
22.0`; no other heat-pump register and no physical KNX bus telegram is in scope.
