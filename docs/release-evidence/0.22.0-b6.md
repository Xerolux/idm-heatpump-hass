# Release Candidate Evidence: 0.22.0-b6

Status: `BLOCKED` for stable promotion; automated validation passed. Fixes
value quantization in external power forwarding on top of 0.22.0-b5.

## Scope

- **Quantized external power writes (fixed, #519):** the external power
  forwarder wrote raw float64 values, so derived sums such as household
  consumption (PV production + grid import + battery flow) carried
  arithmetic noise (e.g. `2.643 + -2.286 = 0.35699999999999976`) into the
  optimistic entity state; the next poll then published the API's
  two-decimal FLOAT readback and the entity visibly alternated between
  both spellings (reporter evidence: activity log alternating `0.36`,
  `0.365`, `0.3569999999999999`). `ExternalPowerForwarder` now rounds
  float writes to two decimals — mirroring the API's
  `round(value * multiplier, 2)` FLOAT decode, so the optimistic state
  equals the readback — and normalizes `-0.0`. `battery_soc` keeps its
  integer path. The written payload now only changes when a value moves
  by ≥ 10 W. The cyclic 3-second refresh cadence is deliberately
  unchanged: GLT inputs are RAM registers (`eeprom_sensitive=False`,
  addresses 74/78/82/84/86 — none in the API's EEPROM-sensitive set),
  some firmwares clear them seconds after the last write (#493), and RAM
  writes cause no write-cycle wear. PR #524.

Motivation: reporter validation feedback on #519 (rounding flaps in the
forwarded values; question about write frequency, answered on the issue).
