## Live upgrade and observation

Completed 2026-10-18 (evening). The reference plant (AERO ALM 6-15,
Navigator 10, firmware `T_NAV10_20.24-1580-g02a20b66f`) was HACS-updated to
b8 at 18:37 UTC. Note for the record: the first post-update poll still
showed the old UCHAR `0.0` because the update had only reloaded the config
entry — a reload does not re-import Python modules, and the running process
still had idm-heatpump 2.14.3 in memory while the version sensor already
reported the freshly installed 2.14.4 from disk. After a full Home Assistant
restart the entity reads **live flow values** (25.8 → 26.5…26.9 → 30.8 L/min
observed over the evening, heating ramping up) — the reference plant's
heat-sink block does serve a live float at 1072 after all; earlier "no TWT,
always `-1.0`" probes had sampled through a second, non-primary connection.

Single-connection rule (documented in Troubleshooting EN/DE): the
Navigator's Modbus TCP server serves one active client. A second concurrent
connection (probe scripts included) receives the not-present sentinel on
optional blocks while the primary keeps live data — direct-API tests on a
running plant are therefore only meaningful with the integration stopped.
The plant's Modbus proxy (ModBridge port 5020) was decommissioned for IDM
afterwards; the entry now connects directly and the SolarEdge gateway on the
same box (port 502) is unaffected. No IDM entries in the Home Assistant
system log after the restart; outdoor temperature, averaged temperature and
the flow readings all plausible. The second live confirmation came from the
reporter of discussion #516 (different plant, live flow signal): b8 was
tested shortly after release and confirmed working.
