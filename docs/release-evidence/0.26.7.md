# Release evidence: 0.26.7

## Scope and release decision

The maintainer explicitly requested a new stable release in the 0.26 series
carrying the fix for issue #668. This record separates observed results from
implementation guarantees; it is not a claim of a seven-day candidate soak,
fleet-wide compatibility or a fresh hardware installation from the published
ZIP. Prepared from the maintainer-authorized session on 2026-11-08; no
maintainer signature is fabricated.

- Candidate: `v0.26.7`; API requirement `idm-heatpump-api[web]==2.16.1`.
- Minimum Home Assistant: 2026.11.0 (verified by the smoke leg in `test_ha/`).
- Trigger: community field report #668 (dnamat88), Navigator 2.0, firmware
  `m_20.23-165-ga41ba74fb`, Modbus + Web, integration 0.26.5.
- Observed input: `hc_a_room_temp` (register 1364) answers -327.22 °C with no
  iDM room sensor wired; conventional on/off thermostats handle the room.
  All other temperatures plausible; advisor health score 97.
- Prior art: the same sentinel class was observed as -327.33 °C (#504) and
  the predictive advisor has treated it as missing since #507.

## Change under test

| Area | Result | Limit |
|---|---|---|
| API 2.16.1 `is_uninitialized_temperature` / `UNINITIALIZED_TEMPERATURE_C` (-300 °C) | Published on PyPI (`v2.16.1`, workflow run 42464292179); imported by the integration as the single rule | Band knowledge from two field observations (#504, #668); high-side garbage has no field evidence and stays flagged |
| Health check `health_implausible_sensor` | Uninitialized band excluded; a -327.22 °C room register no longer trips it; -60 °C still trips | A garbage band only — genuinely implausible values must still alert |
| Room-temperature sensor entity | Unavailable while the register answers ≤ -300 °C; available again with a real reading; unchanged when *hide unused registers* is off (raw-value mode) | Entity-level presentation; the raw value remains visible in diagnostics outcomes |
| Climate / water-heater cards | `current_temperature` is None instead of -327.xx for the garbage band | Presentation only; no write path touched |
| Scope guard | Registers not declared as °C keep publishing a -327.xx value (rule scoped to temperatures) | Evidence covers temperature registers only |

## Interpretation and boundaries

- The controller answers an unwired input with uninitialized memory rather
  than a declared sentinel; the official tables publish no range for
  registers 1364–1376, so the API's range validation cannot catch it. The
  band is the evidence-backed statement — not a documented-range invention.
- No plant with a wired room sensor was retested after the change, and no
  hardware installation from the published ZIP was performed. Confirmation
  on the reporting plant (#668) is still pending.
- The advisor's own plausibility range (0–50 °C, #507) remains independent
  and unchanged; both rules now classify the observed garbage identically.
