<objective>
Make writable controls report unknown state (not a sentinel value) while staying available, and
prove the optimistic write path lifts them out of the unknown state immediately (GitHub issue #172
runtime half; the setpoint portion of #170).

Purpose: A writable GLT/PV input that currently reads `255`/`-1.0` must not show `True` or a bogus
temperature, but it must remain a callable write target. Output: available-but-unknown semantics
for writable controls, sensor filtering preserved, and the existing optimistic write path reused.
</objective>

<interfaces>
Runtime visibility is gated by `IdmEntity.available` (entity.py:133-143), which today returns False
when `self._register.name in coordinator.unused_registers` (the precomputed set rebuilt each poll at
coordinator.py:652-656). State is read from `coordinator.data[register.name]`. Writes go through
`IdmEntity._async_write_register` (entity.py:109) -> `coordinator.async_write_register` (coordinator.py:909),
which performs the optimistic update at coordinator.py:944-953 and schedules `_delayed_refresh`
(coordinator.py:862). This plan must NOT disable `unused_registers`, `is_register_unused`, or
`unsupported_registers` — they stay defensive for read-only and operation analysis.
</interfaces>
